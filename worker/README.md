# 闲鱼自动客服与发货 Worker

`worker/` 是单店铺消息处理与自动发货进程。每个店铺账号分配独立的运行环境、配置与会话边界；Worker 监听闲鱼平台事件，优先执行关键词规则，必要时调用控制面 AI 客服，并在核验官方订单后执行安全的自动发货。

## 运行模式

`AUTOMATION_MODE` 由控制面设置：

- `rules`：纯规则模式，只执行预设关键词回复与基础发货，不初始化 AI 客户端；
- `rules_ai`：规则 + AI 双模，优先匹配关键词规则；未命中且满足条件时由大模型生成回复。

AI 仅负责客服对话建议与转人工决策，无权直接修改订单状态、无权跳过订单核验发货，亦无法跨店铺读取其他账号资料。

## 消息处理机制

1. **多重安全门禁**：收到平台消息后，依次检查会话合法性、消息幂等去重、人工接管状态及营业时间；
2. **规则匹配**：优先匹配当前商品的专属规则，未命中时匹配全店通用规则；
3. **AI 兜底生成**：若规则未命中，装配商品实时事实（价格/库存/SKU）与客服人设请求大模型，并经由代码级反导流与防虚假承诺过滤后发送；
4. **人工回复队列**：人工通过工作台发送的内容进入持久 Outbox，支持最多 8 张图片与文字排队发送，每段确认协议 ACK，失败只重试未完成部分。

## 自动发货安全机制

买家文字消息和模型输出绝不能直接触发自动发货。只有通过闲鱼官方双接口（`HeadInfo` 与 `OrderDetail`）核验买家、卖家、商品 ID 及订单状态（`status == 2` 待发货）全部一致，并在库存事务中成功预留卡密后，才执行发放；遇到任何异常均自动转入后台人工审核待办。
