# 闲鱼自动客服 Worker

`worker/` 是店铺级消息处理与履约进程。每个店铺账号使用独立的运行态、配置和会话边界；Worker 接收平台事件，执行固定规则，按需请求控制面 AI，并在取得完整订单证明后执行受控履约。

## 运行模式

`AUTOMATION_MODE` 由控制面为账号设置：

- `rules`：只执行固定规则和明确配置的基础流程，不创建 AI 客户端。
- `rules_ai`：固定规则优先；未命中且满足条件的问题通过账号作用域的控制面接口请求 AI 回复。

模式只表示执行能力，不代表额外的账号类型或功能授权。无论模式如何设置，账号隔离、人工接管、配置版本复核、订单证明和履约安全闸门都保持有效。

AI 只能生成客服文本或返回人工接管/不回复决策，不能发送兑换码或其他履约资料、改变订单状态、批准人工审核或读取其他店铺的数据。

## 本地安装

从仓库根目录运行：

```bash
./scripts/bootstrap-dev.sh
./scripts/dev-worker.sh
```

Worker 的本地配置文件应保持未跟踪。不要把平台登录态、模型密钥、商品 ID、库存或交付资料写入仓库。

只运行离线测试时不需要真实账号：

```bash
cd worker
.venv/bin/python -m unittest discover -s tests -v
```

## 消息处理边界

收到可信平台事件后，Worker 会校验账号和会话、执行入站幂等、检查人工接管和营业时间、匹配固定规则，并在需要时请求控制面 AI。回复在发送前还会复核自动化状态、AI 配置、规则/设置版本和人工接管状态；过期或不一致的正文不会在延迟、重试或重启恢复时盲目发送。

人工回复进入持久 outbox。一次提交可包含文字、最多 8 张图片或图片加文字；图片按顺序逐张发送，文字最后单独发送，每个部分分别等待协议 ACK，失败只重试尚未确认的部分。协议 ACK 只表示平台协议层接收，不等于买家已读或最终送达。

## 履约安全

买家文字、商品标题和模型输出不能授权自动发货。只有订单号、商品、买家、卖家、状态和数量全部核验成功，并完成库存事务预留后，才允许进入履约流程；异常会进入人工审核或死信边界。

## 测试

默认测试使用脱敏样例、临时目录和模拟上游。真实账号、验证码、安全认证、第三方模型、真实订单和真实发货不属于默认 CI 范围，需要在受控环境中单独验收。

涉及 Worker 的改动至少运行：

```bash
npm run test:worker
npm run test:repository
npm run test:syntax
git diff --check
```
