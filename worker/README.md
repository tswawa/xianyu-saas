# 闲鱼自动客服 Worker

`worker/` 是 DeepWhale 闲鱼客服工作台的店铺级消息与履约进程。每个店铺账号使用独立的运行态、配置和会话边界，Worker 负责接收平台事件、执行确定性规则、按需请求控制面 AI，并在取得完整订单证明后执行受控履约。

## 运行 profile

Worker 的 `AUTOMATION_MODE` 由控制面为账号明确设置，支持两种内部执行 profile：

- `rules`：只执行固定规则和明确配置的基础流程，不创建 AI 客户端；这是仓库模板的默认安全模式。
- `rules_ai`：固定规则仍然优先；未命中且满足条件的实质性买家问题，才通过账号作用域的内部接口请求 AI 回复。Worker 只持有生命周期内的短期内部凭据，不直接管理长期上游密钥。

这两个名称描述的是运行能力边界，不代表会员身份或前端套餐。无论 profile 如何设置，账号隔离、人工接管、配置版本复核、订单证明和履约安全闸门都不变。

AI 只能生成客服文本或返回人工接管/不回复决策，不能：

- 发送兑换码、网盘资料或教程资源；
- 改变订单、付款或履约状态；
- 绕过人工审核；
- 读取其他店铺的配置、会话或运行态。

## 本地安装

从仓库根目录运行 `./scripts/bootstrap-dev.sh`，然后编辑未跟踪的 `worker/.env`。真实 Cookie、Key、商品 ID、库存和交付资料只能放在本机受控运行态文件中，不能写入仓库。

```bash
./scripts/dev-worker.sh
```

不准备连接受控测试账号时，不要启动 Worker。运行全量单测不需要真实账号：

```bash
cd worker
.venv/bin/python -m unittest discover -s tests -v
```

Docker 和 systemd 模板分别位于 `worker/docker-compose.yml` 与 `worker/systemd/`。

## 消息处理边界

收到可信平台事件后，Worker 会依次执行账号/会话校验、入站幂等、人工接管检查、固定规则匹配、必要的 AI 请求、输出安全检查和发送前状态复核。生成的回复必须绑定来源和精确配置版本；配置、规则或自动化状态发生变化时，旧正文会被取消，不会在延迟、重试或重启恢复时盲目发送。

人工回复进入账号私有持久 outbox，使用发送期租约、稳定消息标识和有界重试。平台 ACK 只表示协议接收，不等同于买家已读或最终送达。

## 履约安全

平台提醒或买家文字不能授权自动发货。只有订单号、商品、买家、卖家、状态和数量全部核验成功，并完成库存事务预留后，才允许进入受控履约；异常进入人工审核或死信边界。Worker 不把模型输出当作履约依据。

## 测试与开发约定

默认测试使用脱敏样例、临时目录和模拟上游。真实账号、验证码、安全认证、第三方模型、真实订单和真实发货不属于默认 CI 范围，必须由维护者安排受控验收。

涉及 Worker 的改动至少运行：

```bash
npm run test:worker
npm run test:repository
npm run test:syntax
git diff --check
```
