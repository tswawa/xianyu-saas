# 权限与账号作用域模型

本文档说明 xianyu-saas 的平台角色划分、店铺数据隔离、模型连接权限与业务安全边界。

## 平台角色体系

工作台面向个人与团队自托管运营，无任何会员收费或付费墙限制。用户登录后可使用对应角色的全部功能。

系统提供两种平台角色：

| 功能模块与操作权限 | 管理员 (`admin`) | 普通店主 (`owner`) |
| --- | :---: | :---: |
| 绑定与管理本账号下的店铺、会话、订单与卡密库存 | 允许 | 允许 |
| 配置本店铺规则客服、AI 客服人设与自动发货模板 | 允许 | 允许 |
| 配置和使用个人统一模型连接与智能运维（店铺助手） | 允许 | 允许 |
| 查看系统版本信息与发布检查结果 | 允许 | 允许 |
| 修改个人密码与管理当前活动会话 | 允许 | 允许 |
| 切换平台开放注册开关（用户管理面板） | 允许 | 无 |
| 管理平台用户账号（新建、启停、角色变更） | 允许 | 无 |
| 查看系统安全审计日志 | 允许 | 无 |
| 查看全局运行限制摘要（最大店铺数/并发/内存） | 允许 | 允许 |
| 修改系统全局运行限制配额 | 允许 | 无 |
| 读取其他用户的店铺配置、Cookie、会话、订单或库存 | 无 | 无 |

系统支持配置多名管理员，系统内置保护机制防止停用或降级最后一名活跃管理员账号，避免失去管理权限。

## 店铺与数据隔离

工作台按照「用户账号」与「闲鱼店铺」进行双层数据隔离：

- **店铺凭据与商品快照**：每个店铺的登录会话、Cookie 凭据、商品缓存与同步快照独立存储；
- **客服配置与专属知识库**：店铺级回复规则、AI 人设提示词、商品专属问答文档均保存在各店铺目录；
- **买家会话与订单记录**：买家沟通历史、订单详情、卡密发放记录及日志相互隔离；
- **运行进程与目录隔离**：每个店铺由独立的 Python Worker 进程驱动，使用独立目录管理运行时配置，同时共享宿主机资源。单个店铺的网络抖动、凭据失效或平台限制主要影响该店铺自身，降低对其他店铺正常运行的直接波及。

## 统一模型连接与智能运维

### 统一模型连接

- 统一模型连接在「系统设置」中按用户账号独立维护，供该用户旗下的所有店铺共享使用（包括 AI 客服、知识整理与智能运维）；
- 用户在浏览器输入并提交 API Key 后，由服务端主密钥（`SAAS_AI_MASTER_KEY`，32 字节随机值做标准 Base64 编码）加密存储；后续接口不回显明文密钥，浏览器前端不长期缓存明文；
- 平台管理员也无法查看其他用户的模型连接密钥；
- 历史单个店铺遗留的旧模型配置继续保留，用户可在界面主动选择旧连接并测试验证后完成迁移，旧文件不会自动删除；删除统一模型连接后仅保留修订版本记录，系统不会隐式回退到旧密钥。

### 智能运维（店铺助手）

- 智能运维针对单个店铺提供持久化运维会话；
- 助手通过调用已受权的安全工具直接执行运维操作，并向用户界面实时输出结构化执行回执；
- 支持用户在执行过程中发起停止、重试以及后续追问；
- **授权边界**：运维工具仅限读取和调整当前店铺的知识库条目、回复规则与履约发货配置；
- **明确禁止**：严禁执行任何宿主机系统命令、数据库直接修改、买家消息主动发送、售后退款操作、真实发货执行或批量导出卡密库存；
- 平台审计日志仅记录操作类型、执行摘要与成功失败状态，无法用来提取其他用户的业务配置内容。

## 客服与自动发货安全边界

### AI 客服权限受限

- AI 客服模型仅负责生成推荐回复文本或判断是否转接人工客服；
- 客服模型无权直接调用订单修改接口，无权跳过订单核验，也无权直接向买家发放库存卡密。

### 平台双接口交叉验单

自动发货前，Worker 进程必须调用平台官方双接口核验订单状态：

1. 调用 `HeadInfo` 与 `OrderDetail` 接口，确认订单处于待发货状态（`status == 2`）；
2. 核对买家 ID、卖家账号身份与商品 ID 与本地记录一致；
3. 状态核实无误后，由 Worker 进程按预设模板执行发货与履约；未付款、已关闭或买家身份不符的订单不执行发货。

### 履约模式与库存管理

- **规则履约能力**：自动发货支持自建卡密库自动发放（支持 1-50 件）、网盘提取链接推送以及固定文本资料发送（仅支持单件订单）。网盘资源在平台待发货订单核验通过且资源配置有效时下发；
- **模板草稿状态**：未与具体在售商品关联绑定的高级履约模板处于草稿状态，不会对外生效触发；
- **卡密生命周期**：初次导入且尚未入库的有效卡密可用于初始绑定关联；卡密预留具备受控释放分支（用于处理异常或超时释放），已使用或已撤销的卡密不作为可用库存再次分配。

### 状态语义说明

- `risk_control`：平台接口返回风险控制受限状态，不代表已确认具体原因；
- `verification_required`：平台接口返回需要完成安全核验挑战；
- `risk_cooldown`：服务端对平台同步请求设置的降频与冷却保护，控制重试频次。

### 人工回复队列可靠性

人工在工作台向买家发送消息时，消息先进入持久化 Outbox 队列。系统支持文字与最多 8 张图片按序切段发送，并等待协议 ACK 确认，发送失败时仅重试未确认的切段。人工接管会暂停该会话的自动回复链，不影响整店其他会话与自动化履约。

## 初始化与管理员创建

### 默认首次网页注册

在默认配置（`SAAS_BOOTSTRAP_ENABLED=0`）下，全新数据库首次启动后，访问前端登录页会显示「创建首个管理员账号」入口：

- 该入口无需命令行操作或特定运维令牌，也不受后续注册开关（`SAAS_ALLOW_REGISTRATION=0`）的影响；
- 服务端原子判定首次创建资格，建立首个管理员账号（`admin`）及初始默认店铺；
- 创建账号时同步生成基础配置文件（`redeem_codes.json`、`pan_links.json`、`reply_rules.json`、`automation_settings.json`、`products_config.json`）与 `ai_knowledge` 目录，初始化全部成功后自动完成首登；
- 用户的实际存储路径由后端根据分配的真实用户标识确定，无需人工假定用户 ID 或手动创建目录；
- **部署安全注意事项**：空数据库部署后，任何网络可达的用户均可注册为首位管理员。部署人员应在服务上线后立即完成首位管理员注册，再对外公开访问地址。单纯关闭后续注册无法保护未初始化的空站点。

### 后续用户注册控制

- 首位管理员创建后，后续通过网页注册的新用户角色均为普通店主（`owner`），无法自行申请管理员权限；
- 开放后续注册必须同时满足两个条件：环境变量 `SAAS_ALLOW_REGISTRATION=1`，且系统设置中 `registration_open=1`。任一配置为关闭状态，注册入口立即对公众停用；
- 平台管理员可在用户管理界面对已注册的普通店主账号进行角色调整。

### 运维令牌初始化兼容模式（可选）

对于需要强制受控初始化的生产环境，可配置 `SAAS_BOOTSTRAP_ENABLED=1`：

1. 在环境中配置 `SAAS_BOOTSTRAP_TOKEN_FILE`（指定令牌文件）与 `SAAS_BOOTSTRAP_TRUSTED_SOURCES`（指定受信来源 IP 或网段）；
2. 网页端的无令牌首次注册自动关闭；
3. 运维人员从受信网络访问初始化页面，并输入有效令牌创建初始管理员；
4. 初始化完成后关闭该环境变量并清理令牌文件。

### 历史命令行创建账号的配置补齐

对于历史版本通过控制台命令 `DB.create_user(...)` 创建但未包含初始化数据的账号，在用户凭据核验成功后：

- 仅当其默认店铺从未投入使用、现有配置均为有效默认空文件且不存在真实业务数据时，系统自动补齐缺失的基础配置与知识库目录；
- 若店铺已存在业务数据、自定义文件或文件损坏，系统坚决不覆盖已有文件，保持历史数据完整；
- 补齐逻辑由服务端在对应用户目录下安全执行，不改变账号既有角色。
