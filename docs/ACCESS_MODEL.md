# 权限与账号作用域模型

本文档介绍 xianyu-saas 的账号角色、店铺数据隔离与服务安全边界。

## 平台角色体系

工作台面向自托管运营，登录即可使用所有核心功能（多店铺管理、AI 智能客服、卡密与网盘自动发货等）。

系统提供两种平台角色：

| 功能权限 | 管理员 (`admin`) | 普通店主 (`owner`) |
| --- | :---: | :---: |
| 绑定与管理自己的闲鱼店铺、会话、订单与库存 | ✅ | ✅ |
| 配置关键词规则、AI 客服人设与自动发货模板 | ✅ | ✅ |
| 查看系统版本与更新日志 | ✅ | ✅ |
| 修改个人密码、管理活动会话 | ✅ | ✅ |
| 管理平台注册开关与全局设置 | ✅ | ❌ |
| 管理平台用户账号（添加、启停、角色变更） | ✅ | ❌ |
| 查看平台安全审计日志 | ✅ | ❌ |
| 触发版本更新与系统回滚 | ✅ | ❌ |
| 读取其他用户的店铺数据、Cookie、会话或订单 | ❌ | ❌ |

> 系统支持配置多个管理员，但会自动保护最后一名启用的管理员账号，防止误操作导致失去管理权限。

## 店铺与数据物理隔离

工作台严格按照「用户」和「闲鱼店铺」进行双层数据沙盒隔离：

- **店铺连接与商品数据**：每个店铺的登录会话、连接状态、商品缓存及快照独立保存；
- **客服配置与知识库**：店铺级问答规则、AI 客服人设、商品专属问答均按店铺存储；
- **会话与订单记录**：买家对话、消息历史、订单详情及自动发货记录互不干扰；
- **运行进程隔离**：每个店铺由一个独立的 Python Worker 进程承载，单店铺掉线或风控完全不影响其他店铺正常运行。

## 客服与自动发货安全边界

- **模型凭据保护**：大模型 API Key 仅保存在服务端加密存储中，浏览器前端不会长期持有密钥；
- **AI 权限闸门**：AI 仅负责生成客服回复文本或作出转人工决策，**绝无权直接修改订单状态、无权跳过订单核验发货**；
- **双接口交叉验单**：自动发货前必须调用闲鱼官方双接口（`HeadInfo` 与 `OrderDetail`），严格校验买家 ID、卖家身份、商品 ID 及待发货状态（`status == 2`）；
- **人工回复队列**：人工在工作台发送的消息进入持久 Outbox，支持最多 8 张图片与文本按序逐段发送并等待协议 ACK 确认，失败只重试未送达分段。

## 初始化与管理员创建

### 默认首次网页注册

默认配置（`SAAS_BOOTSTRAP_ENABLED=0`）下，全新数据库允许在登录页「创建首个管理员账号」，不需要终端命令或运维令牌，也不受 `SAAS_ALLOW_REGISTRATION=0` 对后续注册的限制。

- 服务端原子确认首次注册资格，创建首位 `admin` 与默认店铺 `default`；并发请求不会产生多名初始管理员。
- 创建时一起初始化 5 个 JSON 文件：`redeem_codes.json`、`pan_links.json`、`reply_rules.json`、`automation_settings.json`、`products_config.json`，以及 `ai_knowledge` 目录。初始化失败不完成账号创建，成功后网页自动登录。
- 实际 `user_id` 和存储路径由服务确定；不要假定首位用户 ID 为 `1`，也不要手工向猜测的目录写入配置。

> **安全提示**：空站任何能访问者可抢先注册管理员，部署者应先注册再公开分享。关闭后续注册不能保护尚未创建管理员的默认空站。

### 后续网页注册

后续注册仅创建普通店主 `owner`，不能通过注册表单指定管理员角色；必须同时满足 `SAAS_ALLOW_REGISTRATION=1` 和后台设置 `registration_open=1`。任一开关关闭，后续网页注册即关闭。管理员可在后台管理角色，首次注册规则不限制后续按权限增设管理员。

### 显式令牌 bootstrap 兼容（仅运维）

已显式配置 `SAAS_BOOTSTRAP_ENABLED=1` 的部署继续使用原一次性令牌 bootstrap 机制，且不开放无令牌首次注册：
1. 由运维配置 `SAAS_BOOTSTRAP_TOKEN_FILE` 与受信来源 `SAAS_BOOTSTRAP_TRUSTED_SOURCES`；
2. 从受信来源访问初始化页面，使用令牌创建初始管理员；
3. 初始化完成后关闭 bootstrap 开关并移除令牌配置。

此兼容流程不属于普通用户的默认上手步骤。

### 历史 CLI 账号的受限补缺

历史上通过 CLI `DB.create_user(...)` 创建且未传 `initializer` 的账号，在凭据校验成功登录时，仅当默认店铺从未使用、现存文件仅为有效的空默认配置且没有业务数据时，才补齐缺失的初始化文件与 `ai_knowledge` 目录。不会覆盖已有文件，也不会对存在业务数据、损坏文件或已使用的店铺自动补缺或重置。补缺使用服务确定的实际用户和店铺路径，不会改变账号角色。
