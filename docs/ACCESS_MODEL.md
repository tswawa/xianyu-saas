# 权限与服务边界

本文说明当前工作台的账号、店铺和平台管理边界。具体接口行为以当前代码和测试为准。

## 授权模型

项目当前按自用工作台形态运行。历史 `plan`、`active`、`plan_label` 和 `expires_at` 字段仅用于兼容旧客户端或数据，不作为当前经营功能的分级依据。已登录用户的店铺、会话、订单、履约和 AI 能力仍由服务端按接口逐项校验。

平台角色只有两种：

| 能力 | `admin` | `owner` |
| --- | --- | --- |
| 管理自己的店铺、会话、订单、库存和自动化 | 是 | 是 |
| 查看版本和更新说明 | 是 | 是 |
| 修改自己的密码、撤销自己的其他会话 | 是 | 是 |
| 管理平台注册开关和平台设置 | 是 | 否 |
| 管理平台账号、角色、启停和登录锁定 | 是 | 否 |
| 查看结构化安全审计 | 是 | 否 |
| 管理签名版本更新和回滚 | 是 | 否 |
| 读取其他用户的 Cookie、会话正文、订单、库存或买家数据 | 否 | 否 |

可以存在多个管理员，但系统保护最后一个启用的管理员，角色或启停变更会撤销目标账号的活动会话。

## 首位管理员与注册

- 空数据库不会因为收到第一个请求而自动开放注册。
- 首位管理员通过显式开启的 bootstrap 流程创建；部署开关、一次性令牌、可信来源和数据库状态必须同时满足。
- 令牌只通过受控请求头提交，服务端只保存摘要，并在同一事务中创建管理员和消费令牌。
- 初始化完成后应关闭 bootstrap、删除令牌文件并重启相关服务。
- 公开注册由部署上限、数据库开关和已有账号条件共同决定；生产环境建议关闭。

## 账号与店铺隔离

所有店铺数据都绑定当前用户和店铺账号。以下内容按店铺目录或账号作用域隔离：

- 平台连接状态和商品快照；
- 客服规则、AI 配置和商品说明；
- 会话、消息、订单和履约记录；
- Worker 运行态、任务、人工接管和人工回复 outbox。

浏览器可以请求切换店铺，但最终作用域由服务端验证的账号标识决定。客户端提供的目录、商品标题、买家文字或其他标识不能授权跨店铺操作。

## AI 与客服

- AI 连接配置由服务端保存和使用，浏览器不持久化长期模型密钥。
- 当前支持 OpenAI 兼容接口、OpenAI Responses、Anthropic Messages、Google Gemini 和 Ollama 五种格式。
- AI 只能生成客服文本或返回人工接管/不回复决策，不能修改订单、批准履约、发送兑换码或读取其他店铺资料。
- 固定规则优先于 AI；实际发送前会再次检查自动化开关、AI 状态、配置版本、会话作用域和幂等状态。
- 配置缺失或损坏时，自动化安全关闭；不会静默用默认文件覆盖已有账号配置。

## 人工回复

人工回复必须先处于当前会话的人工接管状态，并写入账号私有持久 outbox。一次提交支持文字、最多 8 张图片或图片加文字：

1. 图片按用户选择的顺序逐张发送；
2. 有文字时，文字作为最后一个独立部分发送；
3. 每个部分单独等待平台协议 ACK；
4. 失败恢复时只重试尚未确认的部分；
5. 共享图片只有在不再被活动回复引用时才清理。

协议 ACK 只表示平台协议层接收，不等于买家已读或最终送达。

## 接口边界

- 登录、bootstrap、注册、密码和会话接口只处理账号身份，不返回敏感凭据。
- 店铺连接使用服务端官方二维码流程；浏览器不接收平台 Cookie 或 Token。
- 商品、会话、订单、模板、库存、统计和人工回复接口都要求当前账号/店铺作用域。
- 管理接口要求 `admin` 角色；平台管理员权限不等于读取其他用户业务数据。
- 内部 AI 接口只允许本机 Worker 使用短期账号作用域凭据，不对公网代理。
- 版本更新只接受服务端固定的签名 Release 来源，API 不接受浏览器提交的任意更新地址或路径。

## 部署边界

前端是静态资源，后端提供 FastAPI 控制面，Worker 处理平台消息与履约。Docker 自托管和 Linux systemd 版本化部署是两种独立方式，不应在同一实例混用。真实平台登录、第三方模型、真实订单履约和生产部署需要单独受控验收。
