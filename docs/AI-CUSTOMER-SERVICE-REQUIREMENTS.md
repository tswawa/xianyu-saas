# AI 客服与安全规范

本文档说明 xianyu-saas 0.4.6 的 AI 客服架构、人设配置、上下文装配与发送规则。

## 1. 客服系统架构

规则客服和智能客服有独立开关。两者开启时按以下顺序处理；关闭规则客服后可以直接进入 AI 回复，关闭 AI 后仍可运行规则客服。关闭两类回复不会停止已配置的订单自动发货。

1. **关键词规则优先**：
   - 优先匹配商品专属规则，未命中时匹配店铺通用规则；
    - 规则客服开启且命中规则时返回预设话术，不产生模型调用；
    - 首次咨询与未命中时的固定默认回复属于规则客服设置，不用作 AI 故障时的兜底话术。
2. **大模型回复**：
   - 规则未命中且满足回复条件时，调用配置的大模型接口生成回复；
   - 自动装配商品事实（标题、价格、规格）与知识库内容；
   - 经过站外导流过滤与防虚假承诺校验后发送；
    - 模型临时限流、超时或服务不可用时进行有界重试；配置与鉴权错误直接交由管理者处理；
    - 回复发送受通用延迟、营业时间、会话状态与网络连接状态约束；同一店铺所有对外消息共用串行发送槽，默认前次发送结束后间隔至少 3 秒；较长回复可按句子拆分，链接保持完整。
3. **人工接管**：
   - 操作人员在客服工作台介入某个会话后，触发该会话的人工接管冷却（`manual_takeover_cooldown_seconds`）；
   - 冷却期间仅抑制当前会话的自动回复链，避免与人工冲突；
    - 图片回复可自动进入接管后上传、排队发送；
    - AI 按店主配置决定转人工时保存“待人工”标记，工作台支持全部、未读、接管与待人工筛选；
    - 人工接管不影响其他买家会话，亦不暂停店铺已核验订单的发货流程。

客服仅处理已确认属于当前店铺的商品会话。商品快照或已核验的历史归属提供证明，平台买家昵称用于展示；本账号作为买家的聊天不会触发客服。断线期间的过期消息可供人工查看，不在恢复连接后补发自动回复。

## 2. 统一大模型连接

大模型连接配置归属于系统用户，在系统设置中统一维护（`/api/settings/ai/connection`）。用户在前端输入并提交 API Key，浏览器端后续不回显明文且不进行长期本地缓存。服务端要求提供由 32 字节随机二进制经标准 Base64 编码（44 字符，示例：`base64.b64encode(os.urandom(32)).decode()`）的主密钥（`SAAS_AI_MASTER_KEY`），通过 HKDF 派生子密钥并以 AES-GCM 加密保存凭据。该连接供当前用户管理的所有店铺共用，支持以下功能：
- 店铺日常买家问答的 AI 客服兜底；
- 商品描述中的问答知识提取与整理；
- 店铺助手的多轮运维对话与工具参数组织。

上游模型返回 401、403 等鉴权异常时，通过非本站 401 错误包装返回，避免前端误将模型鉴权失败判定为系统登录会话过期而退出；请求失败后前端按钮恢复可用状态，历史失败请求不污染后续新会话。

系统目前作为单机自托管工作台运行，不设商业化付费会员体系或订阅计费功能。

## 3. 支持的大模型协议

系统适配以下主流调用格式：
- `openai_chat_completions`：标准 OpenAI 兼容接口（兼容 DeepSeek、通义千问、Kimi 等服务商）；
- `openai_responses`：OpenAI Responses API；
- `anthropic_messages`：Anthropic Claude 协议；
- `google_gemini`：Google Gemini API 协议；
- `ollama_chat`：本地部署的 Ollama 接口（本地访问默认关闭；环境变量 `SAAS_AI_ALLOW_OLLAMA_LOCAL=1` 仅针对 `ollama_chat` 开放本地回环与 HTTP 访问例外，普通私网地址仍被拒绝，`SAAS_AI_ALLOW_HTTP_LOCAL` 本身不放开地址限制）。

调用地址遵循系统 SSRF 防御规则。Fake-IP 属于代理与 DNS 环境兼容问题，外部大模型域名需通过真实公网 DNS 解析方可通过安全检查；严禁关闭 SSRF 防护或跳过 TLS 证书校验，禁止将本机临时固定 IP 映射写入通用配置或发布包。

## 4. 人设配置

界面提供两种内置人设和自定义选项。人设说明统一描述表达要求，最多 1200 字；客服名称最多 80 字。人设只影响措辞，不改变商品事实与业务规则。

| 人设 | 标识 | 表达要求 |
| --- | --- | --- |
| 小喵客服 | `catgirl` | 软萌、机灵、亲近人，偶尔带一句“喵”；谈价格、付款和售后时直接说清楚 |
| 薄荷客服 | `mint` | 开朗直爽、元气热心，主动回应问题；遇到故障与售后时放低情绪强度 |
| 自定义 | `custom` | 由店主填写说话方式、回应习惯与分寸 |

切换预设会自动保存；保存期间控件锁定，失败保留草稿并允许手动重试。自定义人设内容在切换时保留。服务端仍接受旧 `friendly`、`professional`、`none` 标识，前端按可编辑的自定义内容呈现。

原有 `tone`、`buyer_address`、`reply_length`、`emoji_level` 四个独立风格字段已退役。旧配置可以读取，但这些字段不再进入模型上下文，后续保存也不保留。需要约束表达时直接写在人设说明中。

### 边界约束与转人工条件
- **禁止承诺（`forbidden_claims`）**：店主填写额外禁止表达的内容，默认为空；商品事实约束、订单核验和反站外交易检查始终生效；
- **转人工规则（`handoff_rules`）**：店主填写需要人工处理的情况，默认为空。配置后模型可按条件转人工；未配置时优先生成符合约束的简短回复，资料不足时只问必要信息，安全校验不通过的内容仍不发送；
- 精确匹配旧版内置默认文案的禁止承诺与转人工规则按未配置处理，另行填写的规则保留。

普通问候和闲聊直接接话，不固定追加商品引导、帮助邀请或反问。涉及商品问题时使用相关资料；被索取内部指令、配置或凭据时用简短回应拒绝，不披露内部内容。内部 JSON 决策只供程序处理，不展示成买家回复。

### 知识整理功能
在商品设置中提供知识整理能力，操作人员粘贴说明文本后调用模型提取常见问答，经人工确认后保存生效。

## 5. 安全过滤门禁

大模型生成的文本在发送前须通过以下校验：

1. **反站外导流过滤**：通过正则表达式匹配微信、QQ、手机号、支付宝等外部联系方式，降低触犯平台违规规则的风险；
2. **防虚假发货拦截**：拦截模型文本中声称“已发货”、“款项已到账”等承诺。发货流程由独立状态机在核验待发货订单后执行；
3. **防重复回复**：对比当前会话近期回复历史，相似度超过阈值时拒绝重复文本，运行时允许一次重新生成尝试；
4. **长消息保护**：仅在 `conservative`（保守）策略下，当买家单次发送文本在去除空白字符后超过 240 字时，自动跳过关键词规则匹配，防止误判长文。

## 6. 对话沙盘与内容预览

工作台提供基于当前大模型配置的内容预览沙盘：
- 沙盘使用当前界面中未保存的店铺与商品草稿进行测试；客服内容为空或未关联商品时支持基础模拟；买家问题必须填写，模型连接必须保持有效；
- 每次提问独立展示本次实际回复、使用资料、内容状态与安全状态，不累积沙盘多轮记忆；未回复时显示转人工、拦截或去重原因；
- 沙盘执行时标记 `sent: false`，不保存当前编辑的配置，不启用正式客服，不向闲鱼发送消息；
- 正式客服仅要求保存有效店铺客服内容并显式启用，商品补充知识并非必填项；
- 沙盘仅用于大模型回复生成与提示词效果预览，不执行 Worker 运行时的关键词规则匹配，不作为履约全流程演练工具。
