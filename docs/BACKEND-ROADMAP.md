# 后端架构与迭代路线图

本文档记录 xianyu-saas 服务端的设计现状与演进规划。

> 说明：早期的规划草案中曾探讨过商业化多级会员与付费方案，当前阶段项目定位为单机自托管运营工作台，无付费会员 UI 与分级计费功能。本文档反映系统当前实际落地的架构能力与后续演进方向。

## 当前已实现的架构基础

- **控制面与 Worker 分离架构**：FastAPI 控制面按账号管理配置与数据，每个启用的店铺由独立受管的 Worker 进程承载，受进程管理器统一调度；
- **进程恢复与状态同步**：在满足 Linux 内核能力与进程启动时间校验前提下，利用 pidfd 机制接管已有 Worker 进程（`bot_manager.adopt`），结合数据库运行时 CAS 机制（`worker_runtimes`）防止进程状态冲突；
- **任务队列与租约机制**：基于 SQLite WAL 模式实现持久化异步任务队列，支持任务租约（`control_leases`）、指数退避重试与死信隔离；商品快照同步由用户请求触发进入队列消费；
- **统一用户级 AI 连接**：用户在系统设置维护全局大模型连接（`/api/settings/ai/connection`）。服务端要求通过环境变量 `SAAS_AI_MASTER_KEY` 提供 32 字节随机二进制经标准 Base64 编码（44 字符，示例：`base64.b64encode(os.urandom(32)).decode()`）的主密钥，通过 HKDF 派生子密钥并以 AES-GCM 加密存储，多店铺的 AI 客服、知识提炼与店铺助手共享该连接；
- **店铺助手（Operations Agent）**：通过 `/api/ops/*` 提供持久会话与配置运维能力。使用受限工具集，直接对商品知识、回复规则与发货绑定执行变更。具备操作租约、单项执行回执记录、步骤取消、追问确认与失败重试恢复能力（执行回执用于单项配置核对，不构成跨文件原子事务）。店铺助手禁止执行一切真实发货动作，禁止向买家发送任何消息，不执行 shell 命令，不导出卡密明文；
- **双引擎客服与安全过滤**：优先匹配商品专属与店铺通用关键词规则，未命中时调用大模型；内置反站外导流、防虚假承诺拦截与回复防死循环熔断；人工接管仅抑制对应会话的回复链；
- **独立自动发货流程**：自动发货独立于客服回复体系，不受人工接管或回复营业时段影响。在接收到付款事件后，调用平台 `HeadInfo` 与 `OrderDetail` 双接口核验订单状态（`status == 2` 待发货）。固定文字资料仅支持单件发货，网盘资料下发共享链接，仅卡密类型扣减库存。发货遇到异常根据类型进入重试、待人工处理等不同状态；
- **运行状态检测**：平台交互状态细分为 `risk_control`（请求受限且保持保护）、`verification_required`（平台明确安全验证）与 `risk_cooldown`（本地冷却阶段，冷却后重检）；
- **多媒体人工回复队列**：人工客服回复支持文字与最多 8 张图片按序排队发送，逐段确认平台 ACK，失败仅重试未送达部分；
- **资源监控与限制**：基于 Linux `/proc` 接口实时采样 Worker 运行状态（CPU 单核基准百分比、物理内存 RSS、地址空间上限 `RLIMIT_AS`）。默认单 Worker 地址空间上限为 400 MiB；并发运行上限初始默认来自 `SAAS_MAX_BOTS`，管理员已保存的数据库并发配置优先生效；单用户店铺数量默认上限为 20（支持在数据库设置中按需调整）。调低配置在下次启动时生效；
- **平台依赖支持说明**：Worker 进程管理与资源监控依赖 Linux 内核接口。Windows 环境下采用原生 Docker 容器部署。

## 后续演进规划

### 1. 稳定性与可靠性增强
- 持续完善长连接异常断开的快速重连机制与心跳保活；
- 优化登录态失效的检测与前端预警提示；
- 持续完善安全审计日志与敏感数据脱敏。

### 2. 通知与协同能力
- 增加外部通知通道（如钉钉、企业微信、飞书 Webhook），在卡密库存不足或需要人工介入时及时提醒；
- 优化客服工作台在大消息量场景下的分页加载与跨标签页状态同步体验；
- 跟进主流大模型供应商新发布的 API 规范适配。

### 3. 数据与分析能力
- 完善店铺日常经营统计，包括咨询量趋势、自动回复命中率与发货转化数据；
- 扩展多媒体消息处理能力。

## 技术选型原则

系统坚持单机自托管、低资源占用路线：采用 FastAPI + SQLite WAL + 受管轻量 Worker 架构，不引入 Redis、Kafka 或 Celery 等外部大型中间件依赖，降低部署与维护门槛。
