# 后端架构与迭代路线图

本文档记录 xianyu-saas 服务端的设计边界与后续规划。

## 当前已稳定的架构基础

- **多租户与单店铺进程隔离**：FastAPI 控制面按账号隔离配置与订单，单店铺专属 Worker 承载连接；
- **健壮的状态与任务恢复**：基于 SQLite WAL 模式，支持异步任务持久化、租约与重试，服务重启后平滑恢复；
- **双引擎客服与安全门禁**：商品专属/全店关键词规则优先，未命中走大模型；内置站外导流过滤、虚假发货拦截与防复读熔断；
- **原子级自动发货**：支持卡密池、网盘资源与固定资料发货，发货前调用闲鱼官方双接口（`HeadInfo` + `OrderDetail`）核验证明，事务加锁防超卖；
- **多媒体人工回复**：人工会话支持最多 8 张图片按序逐张发送并逐段确认协议 ACK，失败仅重试未送达部分；
- **全容器化开箱即用**：支持 Docker Compose 极速启动，数据持久化于本地宿主机 `./data`。

## 演进方向

### P0：稳定性与风控增强
1. 持续优化长连接断线重连、会话保活与异常登录态的主动预警；
2. 完善多店铺 Worker 进程的退出回收与并发内存限制；
3. 增强操作审计日志与数据脱敏机制。

### P1：经营效率与工具链
1. 优化客服工作台的消息搜索、实时翻页与跨标签同步体验；
2. 增加商品自动同步调度、库存不足自动微信/钉钉提醒通道；
3. 完善更多大模型主流 Provider 适配（如 DeepSeek 最新接口协议支持）。

### P2：长期规划
1. 丰富数据报表与销售转化统计；
2. 持续完善自动化测试覆盖率与多平台兼容性。

## 技术选型原则

坚持轻量实用、单机低资源占用：采用 **FastAPI + SQLite WAL + 独立轻量 Worker** 架构，无需强依赖 Redis、Kafka、Celery 等大型中间件，单核 1G/2G 云服务器即可流畅运行。
