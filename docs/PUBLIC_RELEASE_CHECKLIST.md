# 公开发布清单

当前仓库同步目标按用户决定保持 **private**。只有以下项目全部完成并经负责人确认后，才可以切换为 public。

## 历史与素材

- [ ] 从工作区和全部 Git 历史清除 `蒸馏/` 及任何未授权第三方截图。
- [x] 将 `handoff/` 内部协作记忆从公开树排除，架构边界与产品约束已提炼进 `CONTRIBUTING.md`。
- [ ] 重写变更记录和部署文档，删除主机用户名、备份位置、内部域名、运行态路径和内部验收流水。
- [ ] 逐项审阅示例提示词、UI 字体、图片、SVG 和所有外部链接。

## 许可证与合规

- [ ] 确认根 GPL-3.0-only 对原创代码的授权主体和贡献者政策。
- [ ] 核对 `worker/NOTICE.md`、字体 OFL 1.1 文本及所有第三方依赖许可证。
- [ ] 在 README 中明确第三方平台自动化、隐私和服务条款风险。
- [ ] 不宣称真实闲鱼、真实订单、真实 AI provider 或生产部署已验收，除非有单独受控证据。

## 技术验证

- [ ] 从干净导出树运行全量 `npm test`、`git diff --check` 和 secret scan。
- [ ] 构建并核验 Docker 镜像与前端资源的来源与哈希。
- [ ] 验证 nginx/systemd 模板只信任预期代理、拒绝内部路径并使用生产密钥外置方案。
- [ ] 通过最小权限、账号隔离、恢复、数据保留和迁移合同。
- [ ] 目标仓库先以 private 完成 CI、文件清单和许可证识别检查，再由负责人单独授权改为 public。

## 公开后的维护

- [ ] 启用 Secret scanning、Push protection、Dependabot 和分支保护。
- [ ] 指定 CODEOWNERS、漏洞私下报告入口和 Issue 模板维护者。
- [ ] 设定版本、Release notes 和破坏性变更策略。
