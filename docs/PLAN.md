# 产品边界与路线图

本文记录当前产品形态、已建立的稳定边界和后续方向。实现状态以代码、测试和实际部署记录为准。

## 当前产品形态

项目是按用户和店铺账号隔离的客服与自动履约工作台，当前围绕六个业务域组织：运营概览、智能客服、履约中心、订单管理、店铺管理和项目说明。

前端保持少入口和低学习成本；账号隔离、权限、任务恢复、消息幂等、订单证明和履约安全由服务端负责。

## 当前能力

1. 店铺连接、商品同步和多店铺切换按账号作用域运行。
2. 商品、会话、订单、配置、库存和 Worker 运行态相互隔离。
3. 固定规则优先，AI 作为受控客服文本候选。
4. AI 客服支持自然语言店铺/商品内容和五种 provider 格式。
5. 人工回复支持持久 outbox、最多 8 张图片、图片顺序发送、文字最后发送、逐部分 ACK 和未确认部分恢复。
6. 自动履约必须经过完整订单核验和库存事务预留。
7. Docker 自托管与 Linux systemd 版本化发布分别提供部署路径。
8. 缺失或损坏的控制文件会安全关闭自动化，不静默恢复默认配置。

## 后续方向

- 补充平台状态、错误恢复和真实环境验收记录；
- 完善跨设备消息推送、买家已读回执和事件级审计；
- 增强商品变更检测、定时同步、导入导出和运营统计；
- 完善依赖许可证、SBOM、可复现构建和供应链校验；
- 在保持账号隔离的前提下拆分过大的控制面与 Worker 模块。

## 暂不支持

- 其他电商平台适配；
- 自动改价、擦亮、评价、批量搬运或高频营销动作；
- 独立桌面端、移动 App 或浏览器自动化扩张；
- 以 AI 输出直接改变订单、库存或履约状态；
- 用真实账号、真实订单或真实库存替代离线测试样例。
