# 产品定位与发展规划

本文档阐述 xianyu-saas 的产品定位、功能边界与后续规划。

> 说明：早期规划草案中曾包含针对商业化多租户、付费会员层级及订阅制的构想。当前项目定位于单机自托管的闲鱼店铺运营工作台，供店主自主部署使用，不包含商业化付费会员界面与计费逻辑。本文档以当前代码实现为基准进行规划说明。

## 产品定位

xianyu-saas 专为闲鱼卖家设计，旨在解决多账号运营中客服响应不及时、夜间漏单与虚拟商品手动发货耗时的问题。

系统围绕以下核心模块构建：

1. **店铺概览**：监控各店铺运行状态、今日买家消息数、今日自动回复数、今日发货成功数与当前未读会话数，汇总待办事项；
2. **商品与发货**：提供卡片与列表双视图切换，支持请求触发的商品快照同步、发货模板（固定资料单件、网盘链接、卡密）配置与库存管理；
3. **客服工作台**：在同一工作台界面下切换各店铺的即时会话，支持人工随时介入接管（仅抑制当前买家会话的自动回复链，不暂停店铺发货）与包含最多 8 张图片的多媒体回复队列；
4. **店铺助手**：提供针对当前店铺的多轮对话式运维辅助，使用受限工具集执行已授权的知识、规则与发货配置，具备回执记录与失败恢复能力；禁止执行一切真实发货动作，禁止向买家发送任何消息；
5. **订单与记录**：记录经过平台双接口核验的订单明细与自动发货审计日志；
6. **店铺管理与系统设置**：提供平台官方二维码扫码绑定、用户级大模型连接配置（前端输入不回显不缓存，服务端通过 32 字节随机二进制经标准 Base64 编码（示例：`base64.b64encode(os.urandom(32)).decode()`）的 `SAAS_AI_MASTER_KEY` 派生子密钥并以 AES-GCM 加密存储）、系统资源限额调整与账号管理。

## 明确的系统边界

为保障运行安全与轻量稳定，本项目遵守以下原则：

- **合规操作**：不包含批量刷单、高频自动擦亮、未经授权的大规模商品采集搬运等破坏平台秩序的行为；
- **平台核验证明发货**：不凭买家单方面聊天要求发货，必须调用闲鱼平台 `HeadInfo` 与 `OrderDetail` 接口核验订单状态为待发货（`status == 2`）并校验买卖家身份后方可执行发货。发货流程独立于客服回复规则，不受人工接管或营业时段影响；固定文本仅限单件，仅卡密类型扣减库存；发货异常根据类型进入重试或人工审核等对应状态；
- **工具权限边界**：店铺助手工具集仅限当前店铺已授权的只读查询与配置更新，禁止执行一切真实发货动作，禁止直接发送买家消息，不执行 shell 命令，不导出卡密明文；
- **系统与依赖边界**：采用 FastAPI + SQLite WAL + 独立受管 Worker 架构，不依赖 Redis、Kafka 等外部组件。Worker 依赖 Linux 内核接口，在 Windows 环境下推荐采用原生 Docker 容器部署。

## 后续版本规划

- **安全平台更新体系（0.3.0 规划）**：引入低频只读版本探测（默认 6 小时服务端协调，浏览器仅读取本地缓存）、管理员密码再次确认与风险确认升级交互、独立 Docker 更新器（Web 容器不挂载 socket、冷备与代码回滚保护，真实环境验收等待隔离引擎/CI）与独立 systemd 更新服务；
- 接入钉钉、企业微信、飞书等第三方 Webhook 通知渠道，在库存告罄或需要人工处理争议时主动告警；
- 持续跟进主流大模型接口标准与新特性的适配；
- 丰富店铺日常经营数据统计与分析报表；
- 优化长周期会话的消息索引与检索效率。
