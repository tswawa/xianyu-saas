# 工程路线图与边界

更新日期：2026-08-29

本文记录仓库层面的稳定边界和后续工程方向，不记录具体生产主机、备份位置、内部域名或运行态数据。

## 当前产品形态

第一阶段采用自用工作台形态。登录用户可以使用已实现的经营功能，旧订阅字段只保留兼容；前端不展示会员、套餐、支付、续费或升级入口。

工作台固定为六个业务域：运营概览、智能客服、履约中心、订单管理、店铺管理和项目说明。每个业务域使用同一套账号/店铺作用域，不能通过前端隐藏代替后端鉴权。

## 当前架构

- `frontend/` 是静态 HTML、CSS 和 JavaScript，不保存平台凭据；
- `backend/` 是 FastAPI 控制面，负责会话、权限、店铺连接、同步、任务、配置和 Worker 生命周期；
- `backend/job_consumer.py` 是异步同步任务的单写者消费者；
- `worker/` 处理 WebSocket 入站、规则/AI 回复、人工 outbox 和订单证明后的履约；
- `deploy/` 提供 nginx、systemd、Docker 和日志轮转模板；
- `tests/` 与 `worker/tests/` 将账号隔离、幂等、恢复、部署和 UI 边界写成可执行合同。

详细数据流见 [`ARCHITECTURE.md`](ARCHITECTURE.md)。

## 已完成的核心边界

1. 店铺 Cookie、快照、配置、聊天库、履约库和 Worker 运行态按账号目录隔离。
2. 官方二维码是普通店铺连接的主流程，浏览器不接收 Cookie 或 Token。
3. 同步任务使用账号范围租约、有限重试和有界状态，任务载荷不保存 Cookie 原文。
4. 自动履约必须同时核验订单、商品、买家、卖家、状态和数量；买家文字、商品标题和模型输出不能授权发货。
5. AI 只生成客服文本；发送前复核自动化开关、AI 配置和精确版本，配置变化会取消旧草稿。
6. 人工回复通过持久 outbox、租约和稳定消息标识发送；协议 ACK 不等于买家已读。
7. 控制文件缺失或损坏时 fail-closed；显式注册和新店铺初始化是唯一的默认文件播种入口。

## 后续方向

- 补充更多受控平台状态和错误恢复合同；
- 在不破坏账号隔离的前提下拆分过大的控制面和 Worker 模块；
- 增加依赖许可证、SBOM、可复现构建和更严格的供应链校验；
- 完善公开发布前的历史净化、素材审核和贡献者治理；
- 在负责人安排的受控窗口内验证真实扫码、第三方模型、商品同步和履约链路。

## 明确不做的事情

- 不在自动化测试中使用真实账号、真实订单或真实库存；
- 不把生产凭据、日志、数据库、买家内容或备份放入 Git；
- 不以本地健康检查、离线合同或 UI 截图替代生产部署证明；
- 不把未经授权的第三方截图、竞品分析材料或预构建二进制当作公开发布内容。
