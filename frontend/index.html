项目说明书

闲鱼多店铺客服工作台使用说明

本说明面向使用本工作台的店主和维护人员。工作台把多个闲鱼店铺的买家会话、自动回复、商品资料、卡密库存和订单发货集中在一处，日常操作按“连接店铺 → 准备资料 → 配置回复 → 处理会话 → 核验发货”的顺序进行。

一、项目概览

每个店铺各自保存登录状态、商品快照、客服配置、会话记录、订单、模板和库存。切换店铺后页面会重新加载对应数据，上一个店铺未返回的请求结果会被丢弃，因此当前屏幕上的内容始终属于顶部选中的那个店铺。

左侧导航共六个位置，覆盖全部日常操作：

二、日常操作与异常处理

  1. 连接并确认店铺。登录后先在店铺管理确认当前店铺。新增店铺时，用闲鱼 App 扫描页面上由服务端生成的官方二维码，全过程不需要手动填写任何登录凭据。
  2. 同步商品并准备发货资料。在履约中心同步在售商品，为需要自动发货的商品准备发货模板和卡密库存，并补充买家常问的商品说明。
  3. 配置回复方式。先写确定的关键词规则，覆盖价格、发货时间、售后等固定问题；剩余问题再交给 AI 客服，配置后用沙盘连续对话确认口径无误。
  4. 处理会话。在智能客服查看未读消息。遇到议价、退款、纠纷或信息不足，点击人工接管，该会话的自动回复会立即停止，直到你主动恢复。
  5. 核验后发货。系统按平台订单事实逐项核对订单号、商品、买卖双方、订单状态和数量，全部一致才预留库存并发送。

三、技术与安全边界

以下边界由服务端强制执行，界面上的操作无法绕过，维护和排查时请以此为准。

  • 数据隔离。所有读写都绑定当前登录账号与店铺作用域，店铺之间的业务数据不共享。
  • 回复优先级。确定性规则优先，AI 只补充规则未覆盖的问题，人工接管可随时中止自动回复。模型输出无权发货或改动订单。
  • 发货依据。买家发来的文字、商品标题和模型输出都不能作为发货凭证，只有平台订单事实可以。
  • 凭据保护。页面不接收闲鱼 Cookie、Token 或模型明文密钥，长期敏感信息只留在账号私有运行环境或外部密钥系统。

当前验证范围：本地离线测试与本机开发环境健康检查已通过（维护者可运行 npm test 复现）。真实闲鱼账号、真实模型调用、真实订单发货以及 Nginx/systemd 生产部署尚未验收，需按部署文档在独立环境安排受控验证。
