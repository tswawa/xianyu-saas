## 项目简介

xianyu-saas 专为经营闲鱼数字商品的多店主与小团队设计。随着经营规模从单店扩展到多店，运营中常会面临店铺数据交叉混淆、服务重启导致消息重复处理、人工介入时自动化规则持续干扰，以及付款事件难以直接对应发货事实等问题。

本系统通过统一控制台集中管理多店铺业务。底层采用应用层作用域隔离机制，确保各店铺拥有独立的数据目录、配置快照与 Worker 进程。消息链路遵循“规则优先、AI 补充、人工兜底”的流转逻辑；履约链路严格校验平台订单事实，在保障多账号隔离安全的前提下，提供稳定、受控的日常运营支持。

> **当前验证状态说明**：
> 本仓库已通过本地离线测试合同，包含 225 项 Worker 测试、API 鉴权测试与前端 UI 自动化测试。文档中的运行截图与示例均基于本地脱敏测试夹具生成。接入真实闲鱼账号、调用生产模型 API、执行线上真实订单发货以及部署到生产服务器，均需在独立环境中单独验收。

## 真实功能场景

```text
[ 用户在页面操作 ] ──> [ 系统后台处理与状态流转 ] ──> [ 触发边界条件转入人工 ]
```

### 1. 连接并管理多个店铺

- **用户操作**：在“店铺管理”页面点击新增店铺，服务端生成闲鱼官方二维码，用户扫码发起授权流程。授权完成后，可为店铺设置自定义备注名，并在店铺管理页面切换当前操作店铺；顶部导航展示当前店铺上下文。
- **后台处理**：系统按店铺划分独立的数据作用域，分别管理登录态、商品快照、消息会话、客服规则、库存池与专属 Worker。前端切换视图时会自动丢弃过期请求响应，服务端请求全程校验店铺权属。
- **异常与边界**：单个店铺出现登录失效或配置异常时，系统仅停止该店铺名下的自动化任务，其他正常店铺的 Worker 与数据流转继续保持独立运行。

### 2. 同步商品并使用实时商品事实

- **用户操作**：在商品管理页面触发在售商品同步，查看商品标题、简介、价格、库存、SKU 及上下架状态。店主可在补充信息栏填入适用人群、交付说明、规格差异、售后政策与常见问题。
- **后台处理**：平台同步的价格、库存、SKU 和上下架状态作为客观事实，在页面上以只读形式展示。店主填写的补充内容支持使用内置 AI 工具进行排版整理预览，整理结果需店主手动点击确认后才会保存，并作为知识上下文参与客服应答。
- **异常与边界**：AI 整理工具无法修改只读的平台实时价格与上下架状态；平台状态变化在下一次同步后更新本地快照，客服回答继续以最新可信事实为准。

### 3. 配置接入客服流程的 AI

- **用户操作**：在“AI 客服设置”中选择接口类型，支持 OpenAI 兼容接口、OpenAI Responses、Anthropic Messages、Google Gemini 或 Ollama，填入端点地址、模型名称与 API Key，点击测试连通性并保存。随后配置店铺人设、回复语气、回复字数、表情偏好、禁止承诺清单及转人工触发词。
- **后台处理**：控制面负责加密托管长期密钥，Worker 仅通过受控的内部调用执行客服请求，前端与 Worker 均不暴露明文 Key。配置内容形成当前店铺 AI 回复的约束，模型只在客服交互层返回生成回复、请求转人工或保持静默等受限结果。
- **异常与边界**：模型推理结果不具备发货权限，也无法直接变更订单状态；当模型输出命中危险承诺拦截规则或格式校验失败时，该条回复会被阻断发送，等待人工处理或后续消息重新进入流程。

### 4. 在连续对话沙盘中测试应答质量

- **用户操作**：进入“连续对话沙盘”，模拟买家身份连续发送咨询消息，查看系统输出的回复草稿、引用的商品数据依据以及安全审查标记。
- **后台处理**：沙盘调用与 Worker 相同的客服应答引擎，由控制面统一处理配置、商品事实、会话上下文和安全检查，前端负责回显多轮对话结果，用于验证语气匹配度、商品信息引用准确性与转人工规则灵敏度。
- **异常与边界**：沙盘结果只在测试页面回显，不向闲鱼平台发送消息，也不改变真实会话、订单或库存状态。

### 5. 规则、AI 与人工接管协同响应

- **用户操作**：客服人员在“会话工作台”按“全部 / 未读 / 人工接管”筛选会话流，查看买家关联商品，检索历史沟通记录，直接发送快捷短语、文字或图片。
- **后台处理**：
  1. 消息推送到 Worker 后，首先校验店铺归属、会话有效性与幂等时间戳；
  2. 优先匹配关键词、营业时间与首询欢迎语等确定性规则，命中后直接应答；
  3. 规则未覆盖时，交由 AI 引擎结合商品事实生成回复；
  4. 买家意图命中转人工条件或客服主动点击接管后，该会话的自动回复立即挂起；
  5. 客服发送的人工消息写入店铺专属持久化队列，Worker 领取后调用接口发出并等待平台响应。
- **异常与边界**：平台返回的 ACK 状态在界面上标明为“闲鱼已接收”，仅代表平台协议层已受理该请求，不包含买家端已读或实际送达信息。

### 6. 配置发货资料与执行订单履约

- **用户操作**：在“履约中心”为在售商品绑定发货模板，维护卡密库存池，或执行批量发货配置。
- **后台处理**：收到付款事件通知后，Worker 主动向平台拉取订单详情，严格比对订单号、买家 ID、卖家 ID、商品关联 ID、订单状态及购买数量。全要素比对通过后，在数据库事务内整体预留并扣减对应卡密库存。
- **异常与边界**：系统发货依据平台订单事实，买家聊天文本、商品标题说明均不作为发货凭据。一旦出现库存不足、规格数量不匹配、买家信息存疑或订单状态异常，系统停止自动化发货，整单流转至人工复核列表，避免部分发货产生纠纷。

### 7. 在运营概览处理风险与待办

- **用户操作**：打开“运营概览”查看当前店铺连接状态、Worker 运行指标、消息趋势图、待处理异常任务与在售商品概况。针对异常项，可手动标记为“已处理”或重新置为“待处理”。
- **后台处理**：系统聚合各模块的异常事件，包括持久队列发送重试、人工介入申请和人工审核队列，以待办看板形式分类汇聚。
- **异常与边界**：运营概览用于日常巡检与任务调度，不替代订单履约状态机；概览接口对敏感数据执行脱敏处理，不输出明文凭证、库存卡密正文或底层异常堆栈。

## 多店铺隔离机制

系统在应用层将每个店铺作为独立运行环境管理：

1. **权限与路径隔离**：服务端校验用户权属后，按作用域寻址专属目录、数据库与 Worker 实例。
2. **数据实体独立**：登录态、商品快照、应答规则、AI 设定、会话流、发货模板与库存池均独立存储。即使不同店铺存在相同的商品 ID、会话 ID 或订单键，数据仍通过用户与店铺作用域隔离，避免相互覆盖。
3. **并发安全与容错**：切换视图时前端自动丢弃过期的异步响应；账号私有目录使用原子写入与受限权限。单店登录失效或配置异常时，仅停用该店铺的自动化任务，其余店铺保持运行。

*架构细节详见 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。*

## 客服消息流转链路

闲鱼消息推送到 Worker 后，先执行店铺归属、会话匹配、时间戳及幂等性校验，随后写入当前店铺的会话库：

1. **前置过滤**：重复事件直接关联历史记录，异常或过期报文流向受控丢弃或恢复逻辑。
2. **链路判定**：
   - 检查自动化总开关、营业时间、人工接管状态及冷静期；
   - 优先匹配商品级与店铺级规则；
   - 规则未覆盖时，转交统一的 AI 引擎处理；
   - 记录回复来源与使用的配置版本；
   - 最终发出前，再次校验会话状态与配置有效性。
3. **人工消息保障**：人工回复通过 API 写入持久化队列，Worker 基于租约机制领取与有限次数重试，进程重启后可以继续处理原任务。

*平台返回的 ACK 在界面标注为“闲鱼已接收”，仅代表平台协议层接收，不包含买家已读或最终送达信息。*

## AI 引擎职能与边界

- **输入构成**：结合店主填写的店铺说明、客服风格、转人工条件、商品补充信息、商品实时快照及近期对话上下文，无需手动编写 JSON 或系统级 Prompt。
- **输出控制**：模型仅在客服交互层生效，限定输出回复内容、请求转人工或保持静默。生成内容需通过长度限制、格式校验、危险承诺拦截、站外导流过滤及近期重复比对。
- **业务边界**：发卡、订单审核与发货均由独立业务状态机处理，模型结果不直接驱动履约动作。沙盘调试内容仅在测试页面回显，不会发送给闲鱼买家。
- **Provider 支持**：适配 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Google Gemini 及 Ollama Chat。长期模型密钥由控制面加密保存，浏览器端与 Worker 不接触明文。

## 订单与履约机制

1. **严格核验**：收到付款事件后，Worker 读取会话头信息与订单详情，交叉比对订单号、商品、买家、卖家、订单状态及数量。信息不一致时直接转入人工队列，暂停自动发货。
2. **事务预留**：核验通过后，在数据库事务内整体预留卡密库存。若可用库存低于订单需求，整单转交人工跟进，避免部分履约。
3. **平台数据准则**：履约动作严格以平台订单事实为准，聊天正文、商品标题及模型结果均不作为发货判定依据。发送前还会重新核验订单与库存状态。

## 项目结构

- `frontend/`：工作台前端代码与浏览器状态管理。
- `backend/`：FastAPI 控制面，负责身份鉴权、店铺管理、异步任务调度、AI 代理与 Worker 生命周期。
- `backend/job_consumer.py`：异步任务消费者，处理租约、重试与死信。
- `worker/`：承载闲鱼消息监听、规则与 AI 响应、人工回复持久队列及履约状态机。
- `deploy/`：Nginx、systemd、Docker 与日志轮转部署模板。
- `tests/`、`worker/tests/`：接口合同、隔离验证、恢复测试、履约测试与 Playwright UI 测试。

## 本地开发

### 环境依赖

- Ubuntu 22.04 / 24.04 或兼容 Linux 系统；
- Python 3.10+，支持创建 `venv`；
- Node.js 20+、npm 10+；
- Playwright Chromium，用于 UI 合同测试。

### 快速初始化

```bash
git clone https://github.com/tswawa/xianyu-saas.git
cd xianyu-saas
./scripts/bootstrap-dev.sh

# 如需运行浏览器自动化测试
npx playwright install --with-deps chromium
```

初始化脚本将生成未跟踪的 `config/saas.env`、`worker/.env` 与 `.local/` 目录。启动前请确认：

- 本地工作台可配置 `SAAS_PUBLIC_ORIGIN=http://127.0.0.1:4173`；
- `SAAS_TRUSTED_HOSTS` 包含本地访问域名或 IP；
- 本地首次初始化可设置 `SAAS_ALLOW_REGISTRATION=1`，生产环境保持关闭；
- 平台凭证、API Key 与主密钥只保存在未跟踪的私有配置或外部密钥系统中，不能提交到 Git。

### 启动服务

```bash
npm run dev
```

访问：<http://127.0.0.1:4173/xianyu-saas/>

本机开发服务与 Nginx/systemd 生产部署属于不同环境。生产配置与回滚步骤见 [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md)。

详见 [`SECURITY.md`](SECURITY.md)。禁止在 Git 提交、Issue、Pull Request、截图或公开日志中夹带以下数据：

2. 真实订单号、买家信息、聊天记录、卡密数据与网盘链接；
3. 生产数据库、备份包、系统日志、内部域名与网络拓扑。
